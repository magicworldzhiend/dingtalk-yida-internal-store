# 钉钉宜搭公司内部售卖平台

这是一个用于记录和维护“钉钉宜搭公司内部售卖平台”配置代码的仓库。

它**不是一个可直接 `npm install`、`npm run dev` 后运行的 Web 项目**。页面、表单、数据源和权限实际运行在钉钉宜搭租户中；本仓库保存从宜搭中誊录出来的 JSX、CSS、页面 JS、远程数据源参数及业务说明，作为可审查、可追溯、可协作的代码档案。

当前仅同步了首页（`home/`）相关内容，商品详情、我的订单、订单详情和管理端模块会在后续逐步补充。

## 项目目标

面向公司内部员工提供商品浏览、SKU 选择、下单、支付和线下领取能力；面向管理员提供 Banner、类目、商品、库存、订单与发放管理能力。

当前首页已覆盖：

- Swiper Banner 轮播（桌面与手机端响应式展示）；
- 商品搜索与两级类目筛选；
- 搜索/筛选重置与筛选条件回显；
- SPU 与 SKU 的分页累计加载；
- 商品最低价、可用库存聚合展示；
- 下架商品置底、灰度和“已下架”水印展示。

## 技术与运行边界

- 平台：钉钉宜搭专业版；
- 页面形态：自定义页面，PC 与移动端适配以 JSX/CSS 为主；
- 数据存储：宜搭表单，不使用外部业务数据库；
- 代码运行位置：宜搭的 JSX 组件、页面 JS 面板、远程数据源 `didFetch` 回调；
- 本仓库用途：版本记录、代码评审、问题追踪和配置同步，不能替代宜搭发布流程。

```text

   ├─ action-panel.jsx          # 首页「页面 JS」面板代码
   ├─ database.md               # 首页相关宜搭表单和字段说明
   ├─ home-banner/              # Banner JSX 组件
   │  ├─ render.jsx             # JSX 渲染代码
   │  └─ style.css              # 组件样式
   ├─ search-filter/            # 搜索与类目筛选 JSX 组件
   │  ├─ render.jsx
   │  └─ style.css
   ├─ product-list/             # 商品列表 JSX 组件
   │  ├─ render.jsx
   │  └─ style.css
   └─ database/                 # 首页远程数据源配置记录
      ├─ getAvailableBanner/    # 已启用 Banner 配置
      ├─ getAvailableSpu/       # 全部 SPU 分页查询
      ├─ getCategoryList/       # 商品两级类目树
      └─ getSkuStock/           # SKU、价格与库存分页查询
```

每个数据源目录通常包含：

```text
数据源名称/
├─ 数据源名称.json   # 宜搭数据源的请求参数与配置记录
└─ 数据源名称.jsx    # 写入“数据处理 / 请求完成回调函数”的 didFetch
```

`.json` 是人工可读的配置档案，**不是宜搭可直接导入的配置包**；`.jsx` 则需要复制到对应的宜搭编辑位置。

## 首页代码与宜搭位置对应

| 仓库文件 | 宜搭中的编辑位置 | 作用 |
| --- | --- | --- |
| `home/action-panel.jsx` | 首页 → 页面 JS 面板 | Swiper 初始化、商品分页缓存和触底加载 |
| `home/home-banner/render.jsx` | 首页 Banner JSX 组件 | 渲染 Swiper DOM |
| `home/home-banner/style.css` | Banner JSX 组件样式 | Banner 响应式比例与控件样式 |
| `home/search-filter/*` | 首页搜索筛选 JSX 组件 | 搜索、筛选抽屉、回显与重置 |
| `home/product-list/*` | 首页商品列表 JSX 组件 | 商品聚合、下架状态与加载标记 |
| `home/database/*/*.json` | 首页 → 数据源对应配置 | 请求地址、表单 ID、查询参数 |
| `home/database/*/*.jsx` | 数据源 → 数据处理 / `didFetch` | 将接口响应转换为组件可用结构 |

## 数据模型概览

宜搭表单中的记录实例 ID（`formInstId`）与业务主键不是同一个概念。关联、查询和更新前必须确认需要使用哪一个。

| 业务表 | 业务用途 | 首页主要用途 |
| --- | --- | --- |
| 商品类目表 | 一级、二级商品分类 | 构建筛选树 |
| 商品款式表（SPU） | 商品名称、主图、状态、类目 | 商品卡片主体与上下架状态 |
| 商品规格与库存表（SKU） | 规格、价格、可用库存、锁定库存 | 聚合最低价和可售库存 |
| 首页轮播配置表 | Banner 图片、SPU 关联、排序、启用状态 | 首页 Banner |
| 订单表 / 订单明细表 | 下单、支付、领取、完成记录 | 后续订单模块使用 |

## 首页分页机制

首页的“继续下滑”分为两层：

1. **本地展示分页**：每次多展示 4 张已缓存商品卡片；
2. **远程数据分页**：当前缓存已展示完时，调用宜搭数据源请求下一页 SPU；如当前 SPU 缺少对应 SKU，则继续请求 SKU 页直到补齐或 SKU 已全部加载。

当前首页的 SPU 与 SKU 数据源均使用 `pageSize: 10`。如调整该值，必须同步修改 `home/action-panel.jsx` 中的 `pageSize` 常量。

## 开发约定

- 对分页、金额、库存、支付和权限变更必须先验证；
- 图片默认 `object-fit: cover`、居中裁切；
- JSX 函数使用 JSDoc，分页、SKU 补齐、状态同步等关键规则保留行内注释；
- 临时 `console.log` 仅用于验证，验收后必须删除。

## 后续计划目录

后续模块会继续采用“页面目录 + 组件目录 + 数据源目录”的结构。例如：

```text
product-detail/       # 商品详情与 SKU 选择
my-orders/            # 我的订单
order-detail/         # 订单详情
admin/                # 管理端页面
shared/               # 多页面复用的常量、工具或样式（确有复用后再创建）
```
